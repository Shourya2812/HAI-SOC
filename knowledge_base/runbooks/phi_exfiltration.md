# PHI Exfiltration Response Runbook

## Purpose

This operational runbook provides a standardized incident response sequence for SOC analysts investigating potential unauthorized exfiltration or bulk extraction of Protected Health Information (PHI) within the HAI-SOC platform.

## Trigger Conditions

An investigation under this runbook is triggered when the ML anomaly pipeline (`xgboost_v1`, `isolation_forest_v1`) flags a data export event crossing anomaly threshold ($\ge 0.50$), featuring one or more of the following HAI-SOC log schema indicators:

- **Primary Action:** `action == "EXPORT_PHI"` or `action == "QUERY_DATABASE"`
- **Volume Metrics:** `extra.records_accessed > 100` or `extra.bytes_sent > 1,000,000` (1 MB)
- **Timing:** `extra.unusual_hour == True`
- **User / Asset Context:** Mismatch between user `role` (e.g. `SOC_ANALYST`, `ADMINISTRATION`) and `department` (e.g. `IT`, `RADIOLOGY`) accessing clinical patient databases (`destination == "Patient_DB"` or `destination == "PACS_Server"`).
- **Authentication History:** `extra.failed_attempts > 0` recorded immediately prior to successful bulk export.

## Initial Triage

SOC analysts should execute the following 8-step initial triage sequence:

1. **Validate User Identity:** Verify the `user_id` submitting the export request against current shift rosters and active active-directory directory sessions.
2. **Validate Role & Department Scope:** Confirm whether the user's assigned `role` and `department` legitimately require bulk export capabilities for clinical or administrative duties.
3. **Determine Records Accessed:** Review `extra.records_accessed` to quantify the scope of patient records extracted.
4. **Determine Volume Transferred:** Evaluate `extra.bytes_sent` to measure data egress size.
5. **Review Source & Destination:** Inspect the `source` system (e.g. `PACS`, `Database`, `EHR`) and target `destination` (e.g. external network gateway IP or unapproved endpoint device).
6. **Review Timing:** Analyze whether `timestamp` falls within normal operational working hours or coincides with `extra.unusual_hour == True`.
7. **Review Authentication Activity:** Check recent `LOGIN` history for the `user_id` to identify prior authentication failures or credential changes.
8. **Evaluate Legitimacy:** Check for active change tickets, clinical research authorizations, or scheduled system backup tasks that explain the data transfer.

## Evidence Collection

- Preserve raw log records (`log_id`) associated with the export event.
- Export ML anomaly score records (`anomaly_score`, `detector`) from `anomaly_scores`.
- Query `logs_collection` for all session activity generated by `user_id` within a 24-hour window around the trigger `timestamp`.
- *(Future Evidence): Capture network flow pcap files or web proxy HTTP POST request headers when network payload inspection modules are deployed.*

## Containment

If triage indicates potential unauthorized access or suspicious exfiltration:

1. Temporarily revoke or disable active session tokens for `user_id`.
2. Block outbound network connections to the target `destination` IP address at the firewall/gateway level.
3. Isolate the requesting workstation (`device`) from the internal healthcare network.

## Investigation

Analyst must explicitly determine and document:
- **Suspicious Activity:** Anomaly score flagged due to unusual volume/timing, but user is authorized and business purpose is verified (False Positive / Authorized Exception).
- **Confirmed Unauthorized Access:** Account accessed data outside role permissions, but no evidence of external exfiltration.
- **Potential PHI Breach:** Confirmed acquisition or exfiltration of unsecured PHI requiring formal breach risk assessment under 45 CFR § 164.402.

## Eradication / Remediation

- Rotate compromised user credentials across Active Directory and EHR/PACS single-sign-on systems.
- Update Role-Based Access Control (RBAC) policies in information access management systems.
- Terminate unauthorized API keys or background export scripts.

## Recovery

- Re-enable user access following credential rotation and administrative authorization.
- Verify system log integrity and ensure normal audit logging resumes without data gaps.
- Document incident resolution status (`RESOLVED` or `CONTAINED`) in the HAI-SOC incidents module.

## Escalation Criteria

Escalate immediately to the Chief Information Security Officer (CISO) and Privacy Officer if:
- Extracted records involve more than 500 individual patient records (`extra.records_accessed > 500`).
- Target `destination` is an unapproved, external, or blacklisted IP address.
- Active ransomware or credential theft indicators coincide with the export event.

## HAI-SOC Detection Mapping

- **Log Action:** `EXPORT_PHI`, `QUERY_DATABASE`
- **Telemetry Schema Fields:** `user_id`, `role`, `department`, `source`, `destination`, `device`, `severity`, `extra.records_accessed`, `extra.bytes_sent`, `extra.unusual_hour`, `extra.failed_attempts`
- **Anomaly Classifier:** `xgboost_v1`, `isolation_forest_v1`
- **Risk Level Assignment:** `CRITICAL` (score $\ge 0.90$) or `HIGH` (score $\ge 0.75$)
